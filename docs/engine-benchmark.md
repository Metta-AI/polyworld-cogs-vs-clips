# FourScore engine benchmark

Latest simulation optimization results are in
[simulation-performance.md](simulation-performance.md). The measurements below
record the earlier comparison before that optimization.

Measured locally on macOS arm64 on 2026-10-23. Each run processes 10,000
ticks with 32 Cogs on the 120 by 120 FourScore map, seed 1. The three
implementations receive the same prerecorded action stream. Times exclude
compilation, setup, map generation, rendering, bot decisions and file I/O.
Each result is the median of three runs after warmup.

| Engine | Seconds per match | Observed range | Ticks/second |
| --- | ---: | ---: | ---: |
| Original C++, with observations | 5.859 | 5.772–8.665 | 1,707 |
| Original C++, without observations | 0.362 | 0.337–0.438 | 27,648 |
| Polyworld Nim, simulation only | 0.529 | 0.486–0.543 | 18,908 |

Removing observations makes the C++ step about 16.2 times faster. The C++
simulation without observations is about 1.46 times faster than this Nim
simulation. This is a comparison of these implementations, not a language
benchmark. The port has frozen and adapted rules, and the engines do not
produce identical cross-engine trajectories. Both C++ variants retain the
same configurable handlers, rewards and other game work.

The local machine showed substantial timing variation. These are indicative
wall-clock measurements, not results from a dedicated, controlled benchmark
machine. The C++ loop also includes Python action-buffer assignment and one
Python-to-C++ call per tick; the Nim loop calls the simulation directly.

## C++ build and validation

Both C++ variants were freshly compiled using Apple clang++, C++20, `-O3`
and `-DNDEBUG`, sharing the same compiled translation units except for
`mettagrid_c.cpp`. Sources are from the clean C++ subtree of local Metta
revision `03c0f3f13719055a8810f43567fa30492e61cc22`. The original FourScore
configuration comes from cogsguard revision
`a10896a83e2432e992ca9ac6c11a810569355fe3`.

`experiments/build_original.py` copies the C++ sources into
`out/cpp-comparison`. The `CVC_BENCH_NO_OBSERVATIONS` compile flag removes
only the per-step observation-buffer clearing and `_compute_observations`
call. Initial observations during construction remain outside timing.
The original checkout and installed extension are unchanged. The precise
patch is saved in `out/cpp-comparison/no-observations.patch`.

The comparison uses the original generated map with its five-cell outer
border cropped to match the port. The raw generated map is asserted equal
to the reference JSON used for the port. Action IDs are translated by name.
Each C++ run bypasses the Python Simulator wrapper and calls the extension
directly. Profiling is disabled for the wall-clock benchmark and enabled
only in a separate phase-timing pass.

Final exported object data matches exactly between the C++ variants, both
for recorded actions (2,707 objects) and all-idle actions (2,708 objects).
The export includes bound tag methods; these are excluded from comparison
because their addresses differ across processes. Team hold statistics also
match. Validation is saved in `out/cpp-state-validation.json`. The original
timing JSON contains preliminary hashes that included method addresses;
use the separate validation result for state equality.

The separate instrumented C++ run spent 6.922 of 7.461 seconds building
observations, about 93%. The no-observation instrumented run took 0.495
seconds internally. These are separate, instrumented runs and should not
be subtracted from the uninstrumented table above.

Nim was built with Nim 2.2.10 and `-d:release`. All simulation replays
finished at state hash `3548051309`.

## Full matches and Fluffy

Earlier three-run measurements using the same action fixture gave:

| Nim workload | Median seconds | Range |
| --- | ---: | ---: |
| Simulation only | 0.548 | 0.500–0.964 |
| Simulation plus replay hashing/recording in memory | 1.307 | 1.015–1.606 |
| Full match with 32 current BASIC bots | 135.506 | 93.338–157.781 |

The simulation is a small part of live-match cost. A one-second native
stack sample during a live match found 813 of 829 samples inside bot
decisions and 707 in the route stack. This is a sampled interval, not a
whole-match aggregate. It points to path searches and priority-queue work.

`out/fourscore-engine-trace.json` is a bounded Fluffy capture of ticks
1001 through 1020, generated by `experiments/trace_engine.nim`.
Its inclusive timings are 15.43 ms in `decide`, 5.30 ms in `route`, and
4.98 ms in `terrainRoute`, with 640 route calls. Session advancement takes
3.18 ms. Nested spans overlap and must not be added together. This early
20-tick window is much cheaper than the later sampled hotspot and does
not represent the full match.

## Reproduction

Run from the Polyworld CVC repository. These paths identify the local
reference checkouts and Python environment used for this measurement.

```sh
# Generate the shared action fixture and benchmark full Nim matches.
nim check experiments/bench_engines.nim
nim c -d:release -o:out/bench-engines experiments/bench_engines.nim
out/bench-engines > out/bench-nim.csv

# Build matched C++ variants without changing the installed extension.
/Users/me/p/metta/.venv/bin/python experiments/build_original.py
export PYTHONPATH=/tmp/cvc-reference/src:/Users/me/p/polyworld-cogs-vs-clips/out/mapdeps:/Users/me/p/metta/packages/mettagrid/python/src
/Users/me/p/metta/.venv/bin/python experiments/bench_original.py with-obs
/Users/me/p/metta/.venv/bin/python experiments/bench_original.py without-obs

# Recheck simulation-only Nim timing on the existing fixture.
nim check experiments/bench_steps.nim
nim c -d:release -o:out/bench-steps experiments/bench_steps.nim
out/bench-steps > out/bench-nim-steps.csv

# Capture a short Fluffy trace independently of timed benchmarks.
nim r -d:release -o:out/trace-engine experiments/trace_engine.nim
```

Run benchmarks sequentially, with no builds or other benchmark processes
running concurrently. `CVC_BENCH_VALIDATE=1` on the C++ benchmark writes
complete final object exports for both recorded and idle workloads instead
of performing repeated timed and profiled runs. Raw timings are in
`out/bench-cpp-with-obs.json`, `out/bench-cpp-without-obs.json`, and
`out/bench-nim-steps.csv`.
