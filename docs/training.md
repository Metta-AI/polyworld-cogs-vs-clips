# Native observations and PufferLib training

The observation builder and training bridge read the frozen FourScore simulation
state directly. They do not enable graphics, tire tracks, pipes, BASIC policies,
replay hashing or replay recording. Training supplies one cardinal action per
cog and advances all 32 cogs in lockstep. The existing simulation is unchanged.

## Observation contract, version 1

`src/cvc/observations.nim` produces a contiguous `uint8[32, 2048, 3]` batch.
Each token is `(location, feature_id, value)`, following MettaGrid's sparse byte
token approach. Spatial locations pack the local row in the high nibble and the
column in the low nibble. The observer is at `0x66` in a 13 by 13 window.
`0xFE` marks global tokens. Unused entries are `(255,255,255)`.

Objects are ordered by Manhattan distance, then local row and column. Empty
cells and cells outside the map emit no object tokens. Vision uses this port's
square local window, without adding line-of-sight rules. Globals contain tick,
last direction, feedback, team, own-team score, shared bank, bank hearts and
territory owner at the observer. Local objects expose type, owner, equipment,
identity, HP, energy, cargo and hearts where applicable; extractors also expose
resource and remaining stock. Invisible enemies' inventory is never exposed.

The `Feature` enum in `observations.nim` is the canonical frozen schema. Its
ordinal times four is the base feature ID. Values use unsigned little-endian
base-256 digits: the following three feature IDs hold higher bytes when needed.
This preserves HP above 255 and scores above 65535. Object kinds are wall=1,
cog=2, hub=3, junction=4, ship=5, extractor=6, gear=7. IDs do not depend on runtime
configuration. An overflowing observation raises `CvcError` rather than dropping
tokens. Padding is rewritten on every observation.

This is a C++-style observation format for the frozen port, not byte-compatible
MettaGrid checkpoint input. It intentionally does not reintroduce arbitrary
feature maps, query expressions, protocol configuration, speech, diagnostic
features or MettaGrid's generic object handlers. Performance comparisons with
C++ measure each game's observation workload, not identical feature sets or
identical cross-engine simulation trajectories.

## Build and train

```sh
tools/build_training.sh
# In a Python environment with PufferLib 3.0, Torch and NumPy installed:
python training/train.py --seconds 600 --output out/train-baseline
```

On this Mac the tested Python environment is
`/Users/me/p/PufferLib/puffer/bin/python`. The tested PufferLib checkout is
`53d9f3212e20e1ec8fc5317b929570974609ada6`, with Torch 2.8.0. See
`training/requirements.txt` for Python dependencies. PufferLib needs its native
advantage extension built against the installed Torch. This repository still
uses its existing pinned Nim dependencies.

The default is four simultaneous matches, all four teams sharing one policy,
a 64-unit two-layer MLP, five actions (rest, north, east, south, west), and the
actual PufferLib PPO trainer. It runs locally on CPU with four Torch threads.
No GPU service, remote job or paid resource is launched. `--seconds` counts
rollout and optimizer time after setup, finishing the current PPO update before
saving. The default games last the full 10,000 ticks. `--max-ticks` allows shorter
smoke episodes; these ends are treated as terminal, not bootstrap truncations.

Training-only rewards are `0.001 * team score delta`, plus `0.01` for gathering,
`0.02` for depositing and `0.1` for capturing. Shaping does not modify the sim or
the official score. All cogs learn from their own observations. This small flat
MLP is a baseline, not a spatial/recurrent architecture or a trained champion.

Outputs include `metrics.jsonl`, `summary.json`, PufferLib model weights and
optimizer state. `--checkpoint path.pt` starts from model weights with a new
optimizer. The summary records steps, elapsed time, weight change, match stats,
config, source revision and library hash. Training is a synchronous native
shared-buffer integration like GOTA's bridge; the adapter enforces a single
owning thread for the Nim allocation lifetime. Each match automatically resets
with the next deterministic seed after reporting terminal rewards.

```sh
python tests/test_training.py out/libcvc.dylib
python training/evaluate.py out/train-baseline/cvc_RUN/model_cvc_UPDATE.pt
```

Linux builds produce `out/libcvc.so`; pass that path to evaluation/tests. The
training command selects the platform library automatically. Evaluation reloads
the checkpoint and compares separate self-play runs against initial weights on
held-out seeds. It is a checkpoint and behavior check, not a win-rate claim.

## Reproduce profiling

The benchmark requires `out/engine-actions.csv`, generated by the existing
`experiments/bench_engines.nim`. It uses the same 10,000 ticks, 32 cogs and seed 1
as the original C++ benchmark. Map loading and action parsing are outside timing.

```sh
nim check experiments/bench_observations.nim
nim c -d:release -o:out/bench-obs experiments/bench_observations.nim
out/bench-obs
nim c -d:release -d:cvcObsReference -o:out/bench-obs-reference experiments/bench_observations.nim
out/bench-obs-reference
nim r -d:release -d:cvcObsTrace -d:cvcObsReference experiments/bench_observations.nim out/observations-before.json
nim r -d:release -d:cvcObsTrace experiments/bench_observations.nim out/observations-after.json
nim r /Users/me/p/fluffy/src/fluffy.nim out/observations-after.json
```

The reference builder scans the object arrays for each visible cell. The fast
builder reuses station tile indices and builds one occupancy index per match
tick. Both emit identical tokens, checked in tests. Traces cover ticks 9001–9100
and stay below Fluffy's 10,000-event cap. Timed runs disable profiling and report
three runs after warmup. The benchmark also verifies the unchanged final
simulation hash `3548051309`.

# Tools entry points

Run the bounded CPU PufferLib PPO trainer from the repository root:

```sh
sh tools/build_training.sh
/Users/me/p/PufferLib/puffer/bin/python tools/train_puffer.py \
  --seconds 600 --evaluate --output out/puffer-test
```

Use a Python environment with `training/requirements.txt` installed on other
machines. `training/train.py` remains a compatibility entry point. The time
budget covers learning; optional evaluation runs afterward. One PPO update
can finish slightly beyond the deadline. The trainer saves initial weights,
final model and optimizer files, metrics, configuration, source/library hashes,
and a summary. `--checkpoint` loads model weights with a fresh optimizer; it
does not restore the environment or provide exact training continuation.

This is the existing small MLP baseline, not Safa's CNN/LSTM. The simulation
stays frozen and headless. Training rewards remain score delta plus individual
gather/deposit/capture bonuses. No Safa curriculum is implicitly enabled.
See [the source investigation](safa-training-research.md) for the available
curricula and their limitations.

For a direct match diagnostic, use the model path in `summary.json`:

```sh
python tools/evaluate_puffer.py PATH_TO_MODEL.pt \
  --initial out/puffer-test/initial.pt \
  --output out/puffer-test/versus-base.json
```

This plays the initializer and trained policy on the same four full games.
Each controls eight cogs against 24 `base.bas` opponents. The controlled team
rotates across the four corners. These few games are a diagnostic, not a
reliable ladder win-rate estimate. Neither helper uploads a policy.

The October 29 test completed 600.014 seconds, 22,388,736 agent steps,
5,466 updates, and 68 complete training matches. It did not learn useful play:
against base.bas the initializer averaged 0.358525 score and the trained
checkpoint averaged 0, both with zero wins in four games. Trained self-play
also scored zero on four held-out matches. The checkpoint is retained under
`out/puffer-10min-20261029/`; the compact
[test receipt](puffer-test-20261029.json) includes the full measurements.
